## 1. motion-design（whaleyxbt / claude-motion）— 品味的数值化

> 它的定位很关键：「Remotion 教你 API，这份文件教你 taste」。所有数字来自已发布作品，当作**默认值，偏离要有理由**。

### 1.1 时间与确定性（本片全部采纳，是本 skill 第一原则）
- 每个节拍是 `timeline` 里的命名时间点，画面组件与音效 cue sheet **读同一份文件**，画面和声音才能锁死。
  → 本片演化成 `timeline.ts` 的 `SHOTS` + `shotByKey()`；`SFX_TABLE` 全部按 key 派生。
- **绝不在组件里硬编码开始时间**；相对某节拍的偏移（`shotByKey('s02').from + 336`）可以。
- 改时长 = 改 timeline，然后音频自动跟随（本片为此把 SFX 全部改成 key 派生，早期用裸帧号时插镜头就串位）。
- **一切都是 `frame` 的纯函数**：禁止 CSS transition/keyframes、`Math.random()`、`Date`。
  随机数用固定种子 PRNG（`mulberry32`）。理由：渲染是乱序并发的，任何累积状态都会让帧漂移/闪烁。
  ✅ 全片所有粒子场都用固定种子，实现见 `code-recipes.md` §5。

### 1.2 Easing 表（照抄即可）
| 曲线 | 用途 |
|---|---|
| `bezier(0.16, 1, 0.3, 1)` easeOut | 入场、揭示、一切"到达" |
| `bezier(0.6, 0, 0.9, 0.35)` easeIn | 出场——快走、不磨蹭 |
| `bezier(0.65, 0, 0.35, 1)` easeInOut | 两态之间（翻转、停靠、形变） |
| `bezier(0.55, 0, 0.2, 1.12)` overshoot | "落定"的值（滑块爬到刻度） |

**线性只用于连续运动**：旋转、drift、颗粒、走的秒针。
技巧：用 `band(x, a, b)` 从另一个值派生动画（例如字幕跟随水位高度），而不是给每个动画单独一个时钟。

### 1.3 Spring 预设表（物理感才用 spring；文字和运镜用 bezier）
| 手感 | damping / stiffness / mass | 用于 |
|---|---|---|
| 默认落定 | 14 / 140 / 0.8 | 一般 UI 入场 |
| 沉稳 | 15–20 / 140–240 / 0.6–1 | 大面板、长运动 |
| 旋钮卡位 | 12 / 190 / 0.75 | 控制量跳档 |
| pop | 9–11 / 200–230 / 0.7 | 标注、徽章、成功点 |
| 弹性强调 | 8 / 200 | **全片只用一次**的 hero 时刻 |

### 1.4 Timing 数值（最容易被忽略、也最影响"文字太快"）
- 词错帧 ≈ **0.09 s**；列表项/卡片 ≈ **0.2–0.25 s**；环/点 ≈ **0.06 s**。
- 词揭示（Mask 上滑）≈ **0.8 s**。
- **出场时长约是入场的一半**（0.35–0.55 s vs 0.7–1.25 s），出场用 easeIn。
- **场景要重叠**：下一镜在上一镜完全离场前就开始画，硬切到空帧会像"加载中"。
- 打字 ≈ **0.035 s/字**，光标空闲时 ≈2.4 Hz 闪烁。
  ⚠️ 本片 `CornerSub cps=2.2`（≈0.45 s/字）是**故意放慢的戏剧化打字**，不是这个默认值。
- **Reading hold 规则（关键）**：每个"可读状态"落定后必须停留——短句 ≥1 s；超过 3 个词每多一词 +0.25 s；结尾钩子 ≥2 s。
  原话：「15 秒版本因为文字闪太快，最后成了 22 秒版本——**拿不准就停久一点、少动一点**」。
  ✅ 本片用户两次反馈"文字太快/停留再久一点"，解法都是加长 `dur` + 顺序拉开窗口，与此规则完全一致。

### 1.5 Typography / Color / Texture
- 最多 **3 个字族**：display serif / UI sans / mono（标签、数字）。本片收敛为 Noto Sans SC + Noto Serif SC 两族。
- 大字 ≈138px（1080 画布）、紧字距 `-0.02em`、lineHeight 1。本片黑卡 118px/0.14em 是中文宽字距的本地化。
- **每行只有一个 accent**（一个斜体词承载重点）；本片 = 唯一金色 `#E8B04B` 重点词。
- mono 标签：大写、0.2–0.24em、低饱和，属装饰；**观众必须读到的东西一定要大**。
- **手机测试**：把 contact sheet 缩到 360px 宽，关键信息仍要能读。
- 颜色 token 集中在 `C`，组件里不许出现新 hex。**唯一强调色且它要有含义**（变化的东西/答案/赢家）——全是金色就等于没有金色。
- 辉光由**状态**驱动而非时间（`glow = effort`），让光解释故事。
- 纹理：颗粒（opacity≈0.09、每 2 帧重 seed）+ 暗角 + 缓慢漂移的点阵 + 手绘 line boil + 空闲元素"呼吸"（走针、闪光标、慢转）。
  ✅ 本片：Grain + 暗角 + 呼吸辉光 + 浪线 dashoffset 常动。

### 1.6 连续性与反模式（做 QA 时逐条打勾）
- 优先让**物体穿越镜头**而不是硬切；转场必须由画面里某个物体**引发**（五个点合并成一个，变成光圈），不用通用擦除。
- 运动拖尾/挤压从速度派生：`value(f) - value(f-1)`，别假造。
- **全片一个 hero 时刻**，为它铺路，别提前花掉。本片 = 00-E「1.5℃」落定的那道 45° 扫光，全片唯一一次。
- 反模式：所有东西同时淡入 / 所有时长一样 / 起停用线性 / **文字在要被读的时候还在动** / 一帧两个焦点 / 重要内容距边缘 <60px / 第 0 帧是空白黑帧（社交平台拿它当封面）。
  ⚠️ 本片开场是黑卡（不是空白帧），字已完整可读，不违反最后一条。

### 1.7 落地清单
✅ `Grain`（全局）· `RollNum`（结尾 1.1→1.5°C）· `overhead-camera-moves A 式`（s01 升降臂沉降俯拍）· `crash-zoom-punch`（s08 温度计撞停震屏）· `light-play B 式 sheen`（00-E 唯一扫光）。参数见 `techniques.md`。

## 2. motion-design-howseen（Howseen pipeline）— 工程化与声音

> 全套「纯代码、无 AE」的 HTML + `seek(t)` 引擎流程。技术栈不同，但**流程和纪律大量可迁移**。

### 2.1 非协商项（数据诚实）
- **零虚构**：屏幕上的数字要有来源和日期；示意性内容必须标 "Example data / Illustration"；不宣称不存在的功能。
  ✅ 迁移到纪录片：文案修正逐字执行、不润色；「173 个缔约方」这类无法核实的引导句被改成不含数字的逻辑句。
- **字幕不能撒谎**：素材是 Mixkit 下载的就别写"音效由代码生成"。
- 对应它的 `facts.md` 纪律：一场片子建一个"每个数字+来源+日期"文件，没有它就不许上数字。

### 2.2 流程顺序（和本 skill 的"先截图后成片"同源）
`Inputs（缺啥问啥，给推荐默认值）→ BEATMAP.md（BPM→拍长、每镜落在拍上、drop 对准关键视觉）→ 4 stills 看完并修 → 全片渲染 → pops 扫描 → 音频 → mux → 交付`。
- **Nothing still for > 1 s**：任何镜头里得有东西在动。本片对应规则见 pitfalls #9。
- 长片**分 3 段并行渲染**再 concat（它那边是 Playwright；Remotion 用 `--frames` 分段 + concat 同理，但本机实测默认并发已最优，见 pitfalls #13）。
- 音频：两遍 loudnorm 到 **−14 LUFS**、true peak ≤ −1.3 dBTP（给 AAC 留余量）；最终编码 `yuv420p / bt709 / crf16 / AAC 256k / +faststart`。
  ◐ 本片没做整轨母带（BGM+SFX 在 Remotion 内混），但**音量层级**照它的表，见 §5。

### 2.3 确定性 seek 纪律（与 §1.1 互相印证）
- 一切由时间算出：`window.seek = async (t) => {...}`；**无 CSS 过渡、无 timer、无帧间状态**；常量在第一次 seek 前声明完。
- 相机 = 容器上一个 transform，**zoom 在对数空间插值**，绝不 zoom in/out 背靠背。
- 共享元素承载交接（气泡把词带进下一场）；形变里换字的文本要有自己的 mask。
- **Flood**：圆形从源物体扩张，半径要清掉最远角（到 4 角 hypot ×1.05），0.3–0.35 s 完成。
- 捕获卫生：`document.fonts.ready`、暂停所有 CSS 动画、每次 seek 后等 2 个 rAF 再截图。
  → Remotion 等价物：字体用 `@fontsource` 本地加载、不用 CSS 动画、`useCurrentFrame()` 纯函数。
- **任何库只要能 seek 就能用**：GSAP `tl.totalTime(t, true)`、anime.js `anim.seek(ms)`、Lottie `goToAndStop`；只能实时跑的（Spline、CSS/framer 实时）一律禁用。

### 2.4 音乐与 SFX 工作流（本片最大贡献）
- **Music = Mixkit**：`https://assets.mixkit.co/music/<id>/<id>.mp3`；从流派页 HTML 里 grep `music/[0-9]+/[0-9]+\.mp3`（搜索参数 `?q=` 无效）。
- **找 drop 靠能量**，别信自动网格：逐小节低/全频能量 → 在跳变附近 20–50 ms 窗精修；曲目起点 = `drop_in_song - drop_in_film`。
- **SFX = Mixkit**：`https://assets.mixkit.co/active_storage/sfx/<id>/<id>-preview.mp3`。
  已验证 ID 映射：click 1125 / key 2568 / soft tick 1117 / check 1113 / toggle 1120 / toast 2573 /
  pop 2364 / bubble 2357 / soap 2925 / whoosh 1490 / rise 1489 / flip 1485 / impact 1143 /
  shutter 1430 / lens 1433 / sparkle 3083 / success 2865 / bread crunch 118 / 纸张 2379 / 鸟鸣 2472。
- **每条 SFX 按实测峰值（argmax |s|）放置**，gain 0.04–0.3，衰减尾巴；打字音跟随逐字节奏。
  ✅ 本片把 27 条 cue 全部按 `shotByKey().from + 偏移` 钉在 spring 落定帧上。
- 极简/高级感：只用 handful of soft hits，**任何觉得吵的都删掉**。
- 无素材时可在代码里合成：click=衰减正弦、pop=上升正弦、thump=下降正弦、whoosh=加窗噪声（见 §5 sound-design）。

### 2.5 Critique loop（"让模型看自己的帧"）
```bash
ffmpeg -i out/final.mp4 -vf "fps=2,scale=270:-1,tile=6x5" -frames:v 1 out/contact.png        # 全片概览
ffmpeg -ss <t-0.1> -i out/final.mp4 -vf "scale=320:-1,tile=12x1" -frames:v 1 out/strip.png  # 快动作周围 12 帧
ffmpeg -i out/final.mp4 -vf "fps=1,scale=360:-1,tile=5x3" -frames:v 1 out/phone.png          # 手机宽度可读性
```
打开图，按 **1–10 打分**：前 2 秒钩子 / 360px 可读性 / 动效质量（spring、无死帧）/ 变化密度（每 2–4 秒有新东西）/ 构图 / 数据准确 / 音画同步。
写出**最差的 3 个问题 + 时间码**，修掉后只重渲受影响的秒数，重新打分，**每项 ≥8 才收工**。
「当个严厉的动效导演，别当自豪的作者。」
→ 本 skill 落地成 `production-playbook.md` 的验收清单；本片逐帧抓出过"旗子像门板""水没浇到叶子""车轮悬空 14px"。

### 2.6 反「AI 味」规则
一个强调色 · **一次只动一样东西** · 一套形状系统贯穿全片、靠形变而非硬切 · spring 阻尼比 ≥0.72、极轻微过冲、绝不卡通弹跳 ·
禁用彩虹渐变/粒子/发光铬/emoji/lorem ipsum/无意义 3D 翻转 · 字大到手机能读 ·
**静音一句话测试**：把片子静音给人看，若能用一句话概括（"按钮变成了播放器"）就成立，犹豫就是动得太多。
诊断表（丑在哪 → 为什么）：模糊字→过了像素模型，回代码用真 SVG；导出卡顿→有 timer/CSS 过渡，回纯 seek；廉价弹跳→换了 bounce easing，回 spring；循环跳→只对齐了位置没对齐速度。

### 2.7 本片落地与否
◐ **采用**：全部 Mixkit SFX 素材工作流、`light-play B 式 sheen`、4 stills 先行、数据诚实。
❌ **被用户否决**：**节拍脉冲**（全片统一 BPM 缩放）。用户原话「有的镜头本来就是动的，你就不要添加节拍脉冲了」。
  教训：**节拍数据用于音效对位，不做画面脉冲**；本来就有自身运动节奏的场景叠加统一脉冲会打架。
  同理，它那套"每拍 +0.012 缩放 / drop 后 +0.03"在本片完全不适用。

## 3. guizang product video skill — 字幕主语言与硬约束

### 3.1 落地手法（详见 techniques.md）
中英双轨字幕制式（`[[关键词]]` 金色 + NumToken 弹簧数字 + 英文衬线 tracking-in）、
BlackCard 切片错位入场、ConvergeRing / GlyphField / StreakField / OrbitDots 四种场、horizon 发光地平线。
✅ 中段五国的知识与字幕动效基本都来自这套语汇。

### 3.2 硬约束（比效果更值得学）
- **真实功能/真实数据**：正式片至少一项可追溯主张，每项记录发布状态、来源、白话解释；演示数据可以固定但要有证据。
- **原组件、视频尺度**：界面正文在 1080p 成片里 ≥22px；抽象化只用于取景、布局、外层动画。
- **先有方向再写代码**：正式片必须先有 `DIRECTION.md`（选定方向+理由、从题材推导的专属手法、画面规范、镜头表）。
  → 本片对应：用户给的开场/结尾脚本就是方向文档，先确认再动代码；"非必要不更改中间段"。
- **不套模板**：每个视觉手法都要能说出它对应题材的哪一点；案例库是推导示范不是风格包；
  连续做片不原样复用上一支的开场/章节/背景；**同一支片内也要避免所有元素同一种入场、同一种转场**。
  ✅ 本片「反单调」：逐字模糊只留给黑卡大字时刻，日常字幕用整行 rise+fade。
- **清楚排版**：标题中英各一个 span、分别指定字体；中文无衬线；说明句交代"对象、动作、结果"；用户指定字体优先。
- **首帧就是完整画面**：平台抓第 0 帧当封面，前 5–10 帧要是开场段落的完成态，不能是等待入场的空底。
- **完整声音**：默认音乐 + 独立动作音效都进轨，关键反馈听得见、音画同步；用户要求省略时记录原因。
  → 本片用户明确不要配音，但 BGM + 27 条 SFX 齐全，且 BGM 从第 0 帧贯穿。
- **隔离工程**：视频工程自带源码/依赖/构建配置，不污染被展示的源码。
- **授权与真实验收**：素材保留来源和许可；自动检查只证明结构一致，**视觉/语义/听感必须靠实际审阅，没试听就如实说明**。

## 4. video-shotcraft — 仪器测量感

✅ 落地 2 个（参数见 techniques.md）：
- `draw-svg-trace`：半径线/十字准星用 `strokeDasharray=L, strokeDashoffset=L*(1-prog)` 逐段画出，错帧 10f/条、ease-out cubic → 00-E 温度刻度盘。
- `scan-bracket-sweep`：四角括号臂依次弹入（每臂错 4f、8% 过冲）+ 两趟竖向扫光（柔辉 0.07 / 光芯 2.4px 0.85 / 渐变拖尾，clipPath 限定），扫完卸载 → "只有光在读它"。

**可迁移的判断**：数据/测量/取证类画面用"正在被仪器读取"的语汇（描线、取景框、扫描带），
比直接把数字摆上去更有说服力；但**扫光这类仪式感效果全片只能出现一次**。

## 5. review-loop / sound-design / storytelling / video-beats — 验收与决策规则

### 5.1 review-loop（视觉自检清单，已并入 production-playbook.md）
「你看不了视频，但你能看帧。**没看过当前渲染的 contact sheet，不许报告完成**。」
流程：半分辨率 draft → **每个节拍后 0.3 s 取一帧**（让动画落定）拼 4×2、每格标时间码 → 逐条打勾 →
可疑处放大（过渡前后以 0.2 s 步长 scrub、精确到单帧）→ 修 → 回到第 1 步，直到整轮挑不出问题 →
最终 build 后再出一次 sheet + wave。

清单（Composition / Type / Timing / Consistency / Sound）：一帧一个焦点；无意外重叠；重要内容距边 ≥60px；
第 0 帧是真画面不是黑帧；文字没被遮罩裁掉；缩到手机宽度仍可读；**文字在被读时不动**；每个可读状态停留够久（若"停留中"的格子还在动，就是太短）；
场景重叠而非切到空帧；**出场快于入场**；只用 `C` 里的颜色、accent 标出该帧重点；同一元素在各镜长得一样；瞬态落在节拍线上；−14 LUFS ±1、TP ≤ −1 dBFS。
**报告纪律**：说清检查了什么、改了什么、哪张 sheet 能证明；**没重新渲染并看过的修复不许声称完成**。

### 5.2 sound-design（事件→声音映射，◐ 部分采用）
- 「大多数 AI 动效片是哑的，声音才让它像成品」；cue sheet 读**同一份 timeline**，所以声音不会漂。
- 映射表：打字 `typing()`（±4–6ms 抖动、随机增益）/ 词行揭示 whoosh + 落定 blip / 徽章弹入 pop（一串里音高递升）/
  旋钮卡档 click+blip / 描线 scratch / 铺垫 riser（恰好落在 hit 上，全片一次）/ 成功 chime（调内和弦）/
  hero 转场 whoosh 进 + impact 落（全片一次）/ 垫底 pad（hero 处 duck 65%）。
- **Accent, don't narrate**：不是每个运动都要配音，**连续运动（drift、颗粒、旋转）保持安静**。
- 层级：hero 0.25–0.35 / 辅助 0.08–0.2 / pad ≈0.03；声像跟随画面左右（−1…+1）；全片统一一个调，音高随进程上升、在 payoff 解决。
- 母带：−14 LUFS、真实峰值 ≤ −2 dBFS；**主要靠短 hit+静音的混音到不了 −14，别硬压，改用持续声（pad/长尾）补**。
- 验证：出 `wave.png`，每个瞬态要落在节拍线上或稍后；落在两线之间 = 硬编码时间或 WAV 过期。

### 5.3 video-storytelling / hyperframes-video-beats（叙事与整屏卡决策，◐ 参考）
- 四原则里最有用的两条：**一个持续的世界**（物体跨镜延续、改变角色，像被设计过而非拼装）与**相机就是剪辑**（尽量用运镜完成切换）。
- **何时该用整屏黑卡**（本片开场/结尾/事实卡全命中）：钩子 payoff 或"本片讲什么"总览 / 大段落转场 /
  重大数据或研究结果 / 值得记住的论点句 / 短引语或箴言 / 需要观众停下来看的对比。
  规则：**4–12 秒，字要少，只有真实数字或极重要的一个词用强调色**。
- 节奏自检：「观众要记住什么？哪个概念需要视觉结构？哪个统计/对比/转折值得强调？哪里安静到快要走神？」

## 6. 被否决 / 未落地清单（同等重要，避免重犯）

| 项 | 来源 | 用户反馈 / 原因 |
|---|---|---|
| **全片节拍脉冲** | howseen / video-beats | 「有的镜头本来就是动的，你就不要添加节拍脉冲了」→ 节拍只用于音效对位 |
| **配音 / 旁白** | 多套 skill 默认有 VO | 「我们这个视频是不打算加字幕配音的」「我不是让你加配音旁白，而是让你加动效的音效」→ `vo:false` 常驻 |
| **删掉整张数据图** | 用户纠正 | 「我最后只让你删了地图，没有让你把那个数据图删掉啊」→ **只删大陆轮廓，保留地图框与经纬网格**；删改前确认作用范围 |
| **受新脚本影响改风格** | 用户强调 | 「必须延续现在的风格，以现在的风格为准，包括黑屏大字幕形式」→ 新脚本只提供内容/结构，视觉语汇以既有成片为准 |
| **改动中段** | 用户强调 | 「中间的部分最好不要再变了」「非必要不更改」→ 开头/结尾重构时中段一帧不动 |
| **过度装饰** | 逐帧 QA | 旗帜「像门板」→ 缩到 55%；瀑布「像独立白柱」→ 改成贴着冰面的细融溪；光伏板必须贴在屋顶斜面上 |
| **知识卡排版过紧** | 逐帧 QA | 「稍微再大一点点，不用特别靠边」 |
| **时长超红线** | 用户约束 | 超 4'30" 要**立刻上报**，不擅自砍内容；本片最终 243.9s 合规 |

## 7. 为什么 herk-edit-kit 15 个 skill 一个都没用上

`cut-mistakes / cut-silences / edit-video / short-form-edit / short-form-video / make-a-video / gsap / hyperframes* / motion-showreel / sound-design / style-library / video-storytelling / web-sims / website-to-hyperframes`：

**根因是生产范式不同**——它们是「**已有素材 → 剪辑/重排/加特效 → 导出**」的流程（找剪口、检静音、切 B-roll、按 VO 时间戳排图、剪成 Shorts）。
本片是「**代码逐帧生成**」：没有素材时间线、没有剪口、没有静音段、没有源视频，改任何一处都是改一个函数再重渲染，
`cut-*` 类工具天然没有输入；`VO 时间戳 → 字幕` 链路也因为无配音而整条不成立。

**但不是白装**：`sound-design` 的事件→声音映射、`video-storytelling` 的持续世界、`hyperframes-video-beats` 的整屏卡决策表
都被抽象成**规则**吸收到了本文件 §5 和 `production-playbook.md`。
**可迁移的元教训**：评估一个 skill 是否适用，先看它假定的是「素材流」还是「生成流」；
生成流项目里，剪辑类 skill 的价值只剩其中的**品味规则**，工具脚本基本用不上。
